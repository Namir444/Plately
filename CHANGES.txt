Application integration and checkout (2026-09-25)
--------------------------------------------------
- Registered the existing `delivery` Python package while retaining the
  historical `FoodHub` Django app label used by the database and migrations.
- Routed the project URL configuration to `delivery.urls`, explicitly
  registered the existing capitalized template directory, and corrected shared
  stylesheet references.
- Changed cart, checkout, and catalog mutations to CSRF-protected POST actions;
  refreshed the landing and sign-in error pages to use the shared Foodly style.
- Added environment-backed Razorpay settings and a dependency manifest. Checkout
  now reports when payment configuration is unavailable.
- Added persisted orders and item/address snapshots, decimal menu prices, and a
  CSRF-protected payment callback that verifies the Razorpay signature and
  captured payment details before marking an order paid or removing purchased
  items from the cart.
- Added order history and confirmation pages. Reading order history no longer
  clears the cart; the existing `success.html` now displays the verified order
  confirmation.
- Hash passwords for new accounts and upgrade legacy plain-text passwords on a
  successful sign-in; expanded the password column through a new migration.
- Added migration `0003` for menu, cart, and order tables, then applied it to the
  workspace SQLite database without renaming the existing `FoodHub` tables.
- Updated the project documentation to match the implemented flows and remaining
  access-control limitations.
